Расписание БГТУ «Военмех»: пары, карты корпусов, друзья, домашка и уведомления.
Публичное имя — «Расписание военмех». Ярлык Android и заголовок окна Windows в этом дереве ещё подписаны «Военмех - расписание и карты».
Windows и Android 2.1.19 работают без обязательного аккаунта. Телефон и Windows читают уже лежащие расписание и карты без сети.
Браузерная оболочка открыта по адресу, который записан в клиентах. Состав экранов и проверка сайта 2026-09-22: [`docs/STATUS.md`](docs/STATUS.md).

## Развитие платформы

Решение 2026-09-08: «Расписание военмех» — неофициальное приложение только для БГТУ «Военмех», без подразумеваемого одобрения приложения или его ролей университетом. Цель — только русский язык во всём нативном UI Windows/Android и админке; после W7 переключатель языка снят, клиенты только на русском.

Описание «без сервера и облака» относится к исходной офлайн-базе. Решением 2026-09-08 начат локальный API расписания: модульный монолит ASP.NET Core/.NET 8 + PostgreSQL. Решение 2026-09-21 расширяет текущие исходники до веб-клиента, общих аккаунтов, приватной синхронизации и сообществ. Это состояние разработки, а не утверждение о публикации нового релиза или работающем продакшен-сервисе. Офлайн-гость, клиентский кэш и локальные данные сохраняются; миграции без wipe, импорт в аккаунт только по явному согласию.

**Локальный срез API реализован и проверен 2026-09-08.** `src/Zapara.Server` отдаёт группы и расписание из PostgreSQL; `src/Zapara.Ingest` выполняет операторские команды `db-init`, `ingest --file <path>`, `ingest --fetch` и `ingest --refresh`. При ошибке импорта сохраняется последний корректный снимок. Обновление сначала берёт JSON вуза (`/api/schedule`), а `TimetableGroup50.xml` остаётся запасным источником и вшитым первым кадром пустой базы Android. Windows и Android по умолчанию ходят на публичный адрес, уже записанный в клиентах. Пустая `VOGRAPH_API_BASE_URL` на Windows оставляет гостя на локальной базе. Фраза «прод-хостинга нет» описывает 2026-09-08. Границы сайта — в [`docs/STATUS.md`](docs/STATUS.md).

Read-only маршруты: `/health/live`, `/health/ready`, `/api/v1/status`, `/api/v1/groups`, `/api/v1/groups/{groupId}/timetable`. Для согласованного чтения одной версии данные поддерживают `?snapshotId=<UUID>`. Публичного запуска импорта нет.

Проверка: `scripts/timetable/Verify-Milestone.ps1`. Нужны .NET SDK, ASP.NET Core Runtime 8, `curl.exe`, `psql` и отдельно подготовленный локальный PostgreSQL 16 с синтетическими данными. Harness ожидает БД `zapara_test` на loopback-порту `56432`, `ZAPARA_TEST_POSTGRES` и соответствующий libpq `PGSERVICE`; секреты задаются вне репозитория. Если runtime установлен отдельно, `DOTNET8` задаёт путь к его `dotnet.exe`, а `DOTNET_ROOT_X64` — каталог runtime для testhost. Скрипт создаёт и удаляет только собственную схему и процессы API; контейнером управляет оператор. Docker для этих локальных тестов разрешён отдельно. Сквозной прогон использует XML-фикстуры, не подтверждает живую загрузку сайта или готовность продакшена.

Сервер API и постоянно хранимые персональные данные, включая резервные копии и логи с такими данными, остаются в РФ под контролем оператора. Само размещение закон не доказывает. Обмены для входа с VK/Yandex — только необходимый минимум, без логирования секретов и без выгрузки персональных данных в стороннюю аналитику. Одобрение разработки само по себе новую установку или выкладку не разрешает. Доступы, пароли и содержимое конфигурации в документы не записываются. Правила: `AGENTS.md`.

## Веб-приложение и общий аккаунт

Браузерный клиент — **React, TypeScript и Vite** в каталоге `web/`. `npm run build` пишет статику в `src/Zapara.Web/wwwroot`, и Zapara.Server отдаёт оболочку по `/app/`. Отдельный Node-сервер в публичном размещении не нужен. Страницы Razor в `src/Zapara.Server/Pages/Admin` по HTTP не открываются: `/Admin` отвечает 404. Проект `src/Zapara.Web` хранит эту статику и проверки. Входная страница — React.

Разделы оболочки: расписание, неделя, сводка, преподаватели, карты, друзья, домашка, сообщество, группа и настройки. Гость читает расписание без аккаунта, пока отвечает сервер или пока в браузере жива сохранённая копия. Карты сайт каждый раз берёт с сервера. Вход не забирает гостевые записи сам. Где собраны переписка, роли, голосования и общая домашка, написано в [`docs/STATUS.md`](docs/STATUS.md).

### Сборка и локальный запуск

Оболочку собирают из `web/`, затем публикуют сервер. Нужны Node.js, SDK для net8.0 и ASP.NET Core Runtime 8. `ZAPARA_PUBLISH_DIR` — каталог сборки вне репозитория. Команду `npm` запускают из `web/`, не из корня.

    Set-Location web
    npm run build
    dotnet publish src/Zapara.Server -c Release -o "$env:ZAPARA_PUBLISH_DIR"
    dotnet test src/Zapara.Web.Tests

Гостевой запуск из каталога опубликованной сборки:

    dotnet Zapara.Server.dll --urls http://localhost:5199 --Web:Enabled=true --Accounts:Enabled=false --Sync:Enabled=false --Communities:Enabled=false --Admin:Enabled=false

HTTP localhost — только для локальной разработки. Публичный сайт требует HTTPS с доверенным сертификатом: cookie имеют Secure/HttpOnly. Оболочка React не обещает отдельный офлайн-кэш Service Worker. Гостевые расписание и карты на Windows и Android по-прежнему живут без сервера.

### Подготовка модулей

Секреты задаются вне Git через окружение/защищённую конфигурацию. В переменных окружения двоеточие заменяется двойным подчёркиванием: Web__Enabled. Реальные пароли, OAuth-коды, токены и ключи не должны попадать в команды, отчёты и журналы.

| Настройка | Назначение |
| --- | --- |
| Web:Enabled=true | Оболочка и браузерные /web-api/ |
| Accounts:Enabled=true, Accounts:Schema | Аккаунты в отдельной заранее созданной схеме |
| Sync:Enabled=true, Sync:Schema | Приватная синхронизация; требует Accounts |
| Communities:Enabled=true, Communities:Schema | Сообщества; требует Accounts |
| Timetable:Schema | Отдельная схема опубликованных расписаний |
| ConnectionStrings:Accounts, ConnectionStrings:Timetable | Runtime-подключения PostgreSQL |
| ConnectionStrings:AccountsMigration | Операторское подключение миграций; локально допустим runtime DSN |
| Accounts:RegistrationEnabled | Явное разрешение регистрации; без значения — только Development/Testing |
| Web:DataProtectionKeysPath | Абсолютный операторский каталог устойчивых ключей веб-сессий вне публичных файлов |

Имена схем должны различаться. Нумерованные схемы runtime не создаёт и не чинит. Схемы переписки он создаёт сам, когда родители уже смигрированы. До изменений сделайте и проверьте резервную копию. После создания пустых схем и настройки подключений:

    dotnet run --project src/Zapara.AdminCli -- accounts db-migrate
    dotnet run --project src/Zapara.AdminCli -- sync db-migrate
    dotnet run --project src/Zapara.AdminCli -- communities db-migrate
    dotnet run --project src/Zapara.Ingest -- db-init
    dotnet run --project src/Zapara.Ingest -- ingest --refresh

Версии схем, которые поднимает CLI: Accounts 6, Sync 1, Communities 2, Timetable 2. Схему admin создаёт `admin bootstrap`, не обычная миграция. Схемы переписки группы и личной переписки процесс создаёт сам при старте, если родительские таблицы уже есть; номера версии у них нет. Миграции аддитивны. Старые `ingest --fetch` и `ingest --file` сохранены; `--refresh` сначала берёт JSON Военмеха и при отказе валидирует XML, last-good сохраняется. После неопределённого результата публикации сначала проверьте состояние, не запускайте слепой повтор.

Периодический импорт включается отдельно через Timetable:Refresh:Enabled. Настройки IntervalMinutes (60 по умолчанию, минимум 15), RetrySeconds и MaximumRetrySeconds ограничивают частоту/backoff; публичный GET не запускает импорт. Teachers:Refresh:Enabled включает аналогичное ограниченное обновление преподавателей; по умолчанию оно выключено. Учительский last-good находится в памяти процесса: после перезапуска используется явно помеченный пакетный источник. Метаданные показывают источник, время и безопасный код последней ошибки.

Публичные каталоги: `/api/v1/teachers`, `/api/v1/teachers/{id}/timetable`, `/api/v1/maps/manifest` и `/api/v1/maps/assets/{filename}`. Карты, координаты и граф включены в сборку с версиями и контрольными суммами. `/health/live` проверяет процесс; `/health/ready` — пригодное расписание; `/health/platform` — включённые модули, подготовленные нумерованные схемы и читаемый снимок. Одного наличия namespace недостаточно. Проба не смотрит схемы переписки. Выбор учебной группы роль в сообществе не назначает.

### Внешние способы входа и доставка

- VK ID/Яндекс ID: Accounts:External:vk / Accounts:External:yandex — Enabled, ClientId, фиксированный CallbackUri и необходимые провайдеру секреты. Браузерный возврат отделён от Android deep link и Windows loopback.
- Почта: Accounts:Recovery:Smtp — Enabled, Host, Port, Security (starttls или tls), From, при необходимости пара Username/Password. Без SMTP в Development/Testing работает тестовый приёмник, а не настоящая отправка.
- Web Push: Web:Push — Enabled, согласованная пара VAPID PublicKey/PrivateKey, Subject (mailto: или HTTPS); требуется Sync. Подписка включается действием пользователя. Сообщения нейтральные, без текста домашки и имени/группы; отзыв сессии отключает связанную доставку.

Ненастроенная возможность показывается недоступной. Локальные тесты транспорта и Chromium не подтверждают живой вход у провайдера, доставку на физический iPhone или готовность продакшена.

### Резервирование и восстановление

Перед миграцией сохраняйте PostgreSQL через pg_dump --format=custom и проверяйте архив pg_restore --list. Отдельно резервируйте каталог Data Protection и защищённую конфигурацию. На Windows отдельный веб-каталог ключей защищён DPAPI и привязан к соответствующему Windows-контексту; на других ОС оператор обеспечивает права доступа и защиту ключей.

Сначала восстановите архив в **другую пустую тестовую БД**, не поверх работающей: pg_restore --exit-on-error --dbname=<тестовая-БД> <архив>. Затем проверьте версии схем, /health/platform, чтение данных и вход. Потеря ключей сессий может потребовать повторного входа, но не удаления личных записей. До публичного запуска нужны мониторинг, регулярное резервирование и подтверждённое восстановление в выбранном окружении РФ.

Регрессионные RestoreSchemaTests выполняют настоящий pg_dump/pg_restore для исторических схем и проверяют, что ослабленные ограничения по-прежнему отклоняются. Для них отдельно задаются ZAPARA_TEST_POSTGRES (выделенный локальный тестовый PostgreSQL, роль с CREATEDB), ZAPARA_RESTORE_TEST_CONTAINER (имя принадлежащего тесту контейнера PostgreSQL 16) и ZAPARA_RESTORE_TEST_DIRECTORY (абсолютный каталог архивов вне репозитория). Нужны Docker CLI и доступ pg_dump/pg_restore внутри указанного контейнера. Тесты создают случайно именованные отдельные БД и проверяют их архивы перед удалением; рабочую БД и её схемы не восстанавливают поверх существующих данных.

    dotnet test src/Zapara.Server.Tests --filter FullyQualifiedName~RestoreSchemaTests

## Приложения

- **Windows** — Avalonia 12, .NET 8, темы системная / светлая / тёмная, интерфейс только на русском, самообновление с проверкой архива, синхронизация по локальной сети без прав администратора.
- **Android** — Kotlin + Compose 2.0 (дизайн-система, тёмная и светлая темы), нижняя навигация, пакет `ru.zapara.app`, версия 2.1.19, интерфейс только на русском, Android 8.0+.

## Что умеет

Список ниже — гостевое ядро Windows и Android 2.1.19. В тех же исходниках уже есть подгруппы, файлы к домашке, аккаунт, сообщество и текстовый чат группы. Личная переписка, стол старосты и голосования собраны на сайте. Таблица экранов — в [`docs/STATUS.md`](docs/STATUS.md).

- **Расписание: Вчера / Сегодня / Завтра / Неделя / Сводка.** Умный старт: если сегодняшние пары еще не прошли — открывается сегодня, иначе завтра.
- **Четность.** Неделя с 1 сентября = неделя 1 = нечетная. Есть ручная инверсия, если вуз сдвинул неделю.
- **Подгруппы.** Если в одну неделю на один звонок приходят разные преподаватели, человек выбирает один вариант на предмет. Выбор остаётся на устройстве.
- **Столбец «След.»** — дата следующего занятия по предмету.
- **Сводка** — нечетная / четная / обе недели: по дням, типам, предметам, преподавателям, аудиториям.
- **Выбор группы** — все ~420 групп с поиском. Выбирается один раз и запоминается.
- **Переименования предметов** — глобально или только на день недели, плюс заметки. Переживают обновление расписания.
- **Домашние задания** — «через N пар», срок вычисляется сам по расписанию. Статусы: скоро / горит / горит сегодня / просрочено / сдано (далекие скрыты). Текст и срок правятся карандашом у задания.
- **Друзья-светофоры** — до 5 групп: та же аудитория / тот же этаж / тот же корпус / в вузе / нет рядом (потухший). Режим «всегда все» или «только непустые», имена товарищей, добавление через поиск.
- **Карты корпусов офлайн** — 9 планов: ГК 1–4 и УЛК 1–5, встроены в приложение. Аудитория со `*` — это УЛК, без `*` — ГК, `ВЦ` показывает план ГК с пометкой, дистанционные пары — без карты. Карта сама следует за следующей парой, кнопка `◉` у пары показывает её корпус, отдельная кнопка «Карта» — выбор по корпусам. Зум, панорама, на весь экран, «Сбросить вид».
- **Преподаватели** — 700+ человек из расписания вуза: поиск, фильтр «только мои», неделя преподавателя с фильтром Обе / Нечет / Чет, подсветка сегодняшнего дня и пар вашей группы.
- **Уведомления** — два времени: вечернее рассказывает про завтра, утреннее — про сегодня, с переименованными предметами и пометкой горящего ДЗ. На Android — точные будильники, переживают перезагрузку телефона.
- **Синхронизация по локальной сети (Windows)** — перенос переименований, ДЗ, друзей и настроек: JSON-файл и QR, `http://<ip>:8765/sync`. Телефон этот обмен не принимает. Облака у этого пути нет.
- **Автообновление** — Windows и Android-флавор github проверяют релизы на GitHub при старте, скачивают и ставят (Android открывает системный установщик, Windows перезапускается сам). Отключается в настройках. Android-флавор rustore обновляется только через RuStore.

## Установка

- **Android:** `ZAPARA_android-debug.apk` ставится сразу; `ZAPARA_android-release-unsigned.apk` требует подписи. Или через ADB: `adb install -r ZAPARA_android-debug.apk`.
- **Windows:** распаковать `ZAPARA_win-x64.zip` и запустить `Vograph.exe` (нужен .NET 8 Runtime).

## Источники данных

- Студенты: сначала JSON `https://voenmeh.ru/api/schedule/meta` и `/api/schedule/lessons`. Если JSON отвергнут — `TimetableGroup50.xml` (~5.6 МБ, ~420 групп). Пустая база Android сначала показывает вшитый XML.
- Преподаватели: `TimetableLecturer50.xml`, вшит в телефон и Windows. Сервер публикует тот же пакет и обновляет его с сайта вуза, когда включён отдельный работник.
- Карты: планы `karta-*-2022.jpg` (ГК 1–4, УЛК 1–5). В телефон и Windows они вшиты. Сайт берёт их с `/api/v1/maps`.
- Расписание перепроверяется само раз в сутки; переименования и ДЗ при этом не теряются.

## Хранение

- Windows: `%LocalAppData%\Vograph\` — SQLite `vograph.db` (WAL), `ui.json`, `logs\`, кэш карт `maps\`, кэш преподавателей, скачанные обновления `updates\`; `VOGRAPH_DATA_DIR` переопределяет каталог данных, `VOGRAPH_OFFLINE=1` отключает сеть на запуск.
- Android: приватное хранилище приложения — база Room, кэш карт, скачанные APK.

## Сборка из исходников

Windows (PowerShell, .NET 8 SDK):

```powershell
dotnet publish src\Vograph.Desktop\Vograph.Desktop.csproj -c Release -r win-x64 --self-contained false
dotnet test src\Vograph.Desktop.Tests\Vograph.Desktop.Tests.csproj
```

Тесты (xunit + headless Avalonia, кадры в `VOGRAPH_FRAMES_DIR`)

```powershell
# Реальный прогон опубликованного клиента (FlaUI), кадры и отчёт — вне репозитория:
dotnet run --project src\Vograph.Desktop.UiVerify -- --exe <путь>\publish\Vograph.exe --out <каталог отчёта>
```

Android:

```powershell
cd android
.\gradlew.bat :app:assembleGithubDebug
.\gradlew.bat :app:testGithubDebugUnitTest
.\gradlew.bat :app:assembleRustoreRelease
```

Каждая новая версия выходит **двумя Android-сборками с одним номером** (`versionName` / `versionCode`):

- **GitHub** (`assembleGithubDebug`) — с самообновлением. В релиз `vX.Y.Z` кладут `ZAPARA_android-debug.apk` и `ZAPARA_win-x64.zip`.
- **RuStore** (`assembleRustoreRelease`) — без самообновления и без `REQUEST_INSTALL_PACKAGES`. Этот APK в GitHub-релиз не прилагают: правила магазина запрещают обновление с GitHub, а автообновление клиента иначе может скачать не тот файл. RuStore обновляется через магазин; ранние сборки — на GitHub.

Перед релизом поднимают `versionName`/`versionCode`, `AutoUpdate.CURRENT_TAG`, Windows `Version` и `CurrentTagWindows`.
