# Военмех - расписание и карты

Расписание БГТУ «Военмех»: пары, карты корпусов, друзья, домашка и уведомления.
Два приложения с общей логикой — Windows и Android. Офлайн из коробки, без сервера и облака.

## Развитие платформы

Решение 2026-09-08: Zapara — неофициальное приложение только для БГТУ «Военмех», без подразумеваемого одобрения приложения или его ролей университетом. Цель — только русский язык во всём нативном UI Windows/Android и админке; после W7 переключатель языка снят, клиенты только на русском.

Описание «без сервера и облака» относится к исходной офлайн-базе. Одобрена разработка первого локального среза API расписания: модульный монолит ASP.NET Core/.NET 8 + PostgreSQL. Аккаунты, VK ID/Yandex ID/пароль, приватный sync и сообщества — будущие этапы, не поставленные здесь возможности. Офлайн-гость, клиентский кэш и локальные данные сохраняются; миграции без wipe, импорт в аккаунт только по явному согласию.

**Локальный срез API реализован и проверен 2026-09-08.** `src/Zapara.Server` отдаёт группы и расписание из PostgreSQL; `src/Zapara.Ingest` выполняет операторские команды `db-init`, `ingest --file <path>` и `ingest --fetch` для фиксированного источника Военмеха. При ошибке импорта сохраняется последний корректный снимок. Клиенты по умолчанию читают XML вуза; локальный API — только если задан base URL. Прод-хостинга API нет.

Read-only маршруты: `/health/live`, `/health/ready`, `/api/v1/status`, `/api/v1/groups`, `/api/v1/groups/{groupId}/timetable`. Для согласованного чтения одной версии данные поддерживают `?snapshotId=<UUID>`. Публичного запуска импорта нет.

Проверка: `scripts/timetable/Verify-Milestone.ps1`. Нужны .NET SDK, ASP.NET Core Runtime 8, `curl.exe`, `psql` и отдельно подготовленный локальный PostgreSQL 16 с синтетическими данными. Harness ожидает БД `zapara_test` на loopback-порту `56432`, `ZAPARA_TEST_POSTGRES` и соответствующий libpq `PGSERVICE`; секреты задаются вне репозитория. Если runtime установлен отдельно, `DOTNET8` задаёт путь к его `dotnet.exe`, а `DOTNET_ROOT_X64` — каталог runtime для testhost. Скрипт создаёт и удаляет только собственную схему и процессы API; контейнером управляет оператор. Docker для этих локальных тестов разрешён отдельно. Сквозной прогон использует XML-фикстуры, не подтверждает живую загрузку сайта или готовность продакшена.

Сервер API и постоянно хранимые персональные данные, включая резервные копии и логи с такими данными, должны оставаться в РФ под контролем оператора; само размещение не гарантирует соблюдения законодательства. Обмены для входа с VK/Yandex — только необходимый минимум, без логирования секретов и непреднамеренного экспорта персональных данных в стороннюю аналитику. Провайдер/машина, домен, доступы, конфигурация PostgreSQL и runtime ещё не предоставлены; одобрение разработки не разрешает установки или прод-деплой. Правила: `AGENTS.md`.

## Приложения

- **Windows** — Avalonia 12, .NET 8, две темы (тёмная/светлая), интерфейс только на русском, самообновление с проверкой архива, синхронизация по локальной сети без прав администратора.
- **Android** — Kotlin + Compose 2.0 (дизайн-система, тёмная и светлая темы), нижняя навигация, пакет `ru.zapara.app`, версия 2.0.0, интерфейс только на русском, Android 8.0+.

## Что умеет

- **Расписание: Вчера / Сегодня / Завтра / Неделя / Сводка.** Умный старт: если сегодняшние пары еще не прошли — открывается сегодня, иначе завтра.
- **Четность.** Неделя с 1 сентября = неделя 1 = нечетная. Есть ручная инверсия, если вуз сдвинул неделю.
- **Столбец «След.»** — дата следующего занятия по предмету.
- **Сводка** — нечетная / четная / обе недели: по дням, типам, предметам, преподавателям, аудиториям.
- **Выбор группы** — все ~420 групп с поиском. Выбирается один раз и запоминается.
- **Переименования предметов** — глобально или только на день недели, плюс заметки. Переживают обновление расписания.
- **Домашние задания** — «через N пар», срок вычисляется сам по расписанию. Статусы: скоро / горит / горит сегодня / просрочено / сдано (далекие скрыты). Текст и срок правятся карандашом у задания.
- **Друзья-светофоры** — до 5 групп: та же аудитория / тот же этаж / тот же корпус / в вузе / нет рядом (потухший). Режим «всегда все» или «только непустые», имена товарищей, добавление через поиск.
- **Карты корпусов офлайн** — 9 планов: ГК 1–4 и УЛК 1–5, встроены в приложение. Аудитория со `*` — это УЛК, без `*` — ГК, `ВЦ` показывает план ГК с пометкой, дистанционные пары — без карты. Карта сама следует за следующей парой, кнопка `◉` у пары показывает её корпус, отдельная кнопка «Карта» — выбор по корпусам. Зум, панорама, на весь экран, «Сбросить вид».
- **Преподаватели** — 700+ человек из расписания вуза: поиск, фильтр «только мои», неделя преподавателя с фильтром Обе / Нечет / Чет, подсветка сегодняшнего дня и пар вашей группы.
- **Уведомления** — два времени: вечернее рассказывает про завтра, утреннее — про сегодня, с переименованными предметами и пометкой горящего ДЗ. На Android — точные будильники, переживают перезагрузку телефона.
- **Синхронизация по локальной сети (Windows)** — перенос переименований, ДЗ, друзей и настроек между устройствами: JSON-файл + QR + `http://<ip>:8765/sync`. Без облака.
- **Автообновление** — оба приложения сами проверяют релизы на GitHub при старте, скачивают и ставят (Android открывает системный установщик, Windows перезапускается сам). Отключается в настройках.

## Установка

- **Android:** `ZAPARA_android-debug.apk` ставится сразу; `ZAPARA_android-release-unsigned.apk` требует подписи. Или через ADB: `adb install -r ZAPARA_android-debug.apk`.
- **Windows:** распаковать `ZAPARA_win-x64.zip` и запустить `Vograph.exe` (нужен .NET 8 Runtime).

## Источники данных

- Студенты: `https://voenmeh.ru/obrazovanie/timetables/` → `.../_voenmeh_grafics/TimetableGroup50.xml` (~5.6 МБ, ~420 групп).
- Преподаватели: страница расписания преподавателей → `TimetableLecturer50.xml` (встроен в приложения + кэш).
- Карты: `https://voenmeh.ru/openmap/` → планы `karta-*-2022.jpg` (ГК 1–4, УЛК 1–5), встроены в приложения.
- Расписание перепроверяется само раз в сутки (`HEAD If-Modified-Since`); переименования и ДЗ при этом не теряются.

## Хранение

- Windows: `%LocalAppData%\Vograph\` — SQLite `vograph.db` (WAL), `ui.json`, `logs\`, кэш карт `maps\`, кэш преподавателей, скачанные обновления `updates\`; `VOGRAPH_DATA_DIR` переопределяет каталог данных, `VOGRAPH_OFFLINE=1` отключает сеть на запуск.
- Android: приватное хранилище приложения — база Room, кэш карт, скачанные APK.

## Сборка из исходников

Windows (PowerShell, .NET 8 SDK):

```powershell
dotnet publish src\Vograph.Desktop\Vograph.Desktop.csproj -c Release -r win-x64 --self-contained false
dotnet test src\Vograph.Desktop.Tests\Vograph.Desktop.Tests.csproj
```

Тесты (xunit + headless Avalonia, кадры в `VOGRAPH_FRAMES_DIR`)

```powershell
# Реальный прогон опубликованного клиента (FlaUI), кадры и отчёт — вне репозитория:
dotnet run --project src\Vograph.Desktop.UiVerify -- --exe <путь>\publish\Vograph.exe --out <каталог отчёта>
```

Android:

```powershell
cd android
.\gradlew.bat :app:assembleGithubDebug
.\gradlew.bat :app:testGithubDebugUnitTest
# Сборка для RuStore (без самообновления): :app:assembleRustoreRelease
```

## Структура

```text
src/Vograph.Desktop/         # Windows-клиент (Avalonia): Shell, Features/<раздел>, Dialogs, Theme, Domain, Assets (планы, coords.json, преподаватели)
src/Vograph.Desktop.Tests/   # xunit.v3 + Avalonia.Headless: ViewModel-тесты и кадры разделов
src/Vograph.Desktop.UiVerify/   # Драйвер реального приложения (FlaUI): проходит разделы, диалоги, карты; отчёт и кадры в --out
src/Vograph.Core/            # Общая логика Windows: парсер, четность, расписание, ДЗ, карты, sync
android/app/src/main/        # Android-клиент: Compose-экраны, Room, будильники, автообновление
docs/API.md                  # Разбор XML/XSL/parity/openmap/lecturer
docs/PROGRESS.md             # Верификация Windows по фазам
docs/PROGRESS_ANDROID.md     # Верификация Android по фазам
docs/dist/                   # Готовые сборки прошлых версий
```
