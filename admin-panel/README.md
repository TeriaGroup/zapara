# Панель оператора

Локальное приложение Laravel / Filament рядом с «Расписание военмех».
Оно ходит в те же схемы PostgreSQL, включая `operator`. В git этот каталог не входит, в compose сервера его нет.

Zapara.Server страницы `/Admin` не отдаёт: эти пути отвечают 404 в любом регистре, даже при `Admin:Enabled=true`
(страницы Razor не маршрутизируются, это закреплено тестом `AdminAuthTests`). Исходники Razor лежат в
`src/Zapara.Server/Pages/Admin`; рабочая админка — эта панель Filament, у Razor-версии второго фактора нет.

Секреты, `.env`, `vendor` и локальную sqlite в репозиторий не класть.
Картина продукта — `docs/STATUS.md`.

## Двухфакторная защита (TOTP)

Вход в панель поддерживает одноразовые коды из приложения-аутентификатора (RFC 6238: Google Authenticator, Aegis, 2FAS, 1Password и т. п.) и одноразовые коды восстановления. Используется встроенный MFA Filament (`AppAuthentication`), новых пакетов нет.

Секрет и хэши кодов восстановления лежат в таблице `admin_mfa_credentials` (схема `DB_SCHEMA`, по умолчанию `public`, рядом с `cache`/`jobs`). Схему `accounts` сервера панель не меняет. Секрет зашифрован `APP_KEY`: при смене ключа старый указывают в `APP_PREVIOUS_KEYS`, иначе администраторам придётся подключать TOTP заново.

### Как администратору подключить

1. Войти в панель по логину и паролю.
2. Меню пользователя (справа вверху) → «Двухфакторная защита» (`/admin/security`).
3. «Настроить» у приложения-аутентификатора, отсканировать QR-код (или ввести ключ вручную), ввести текущий код.
4. Сохранить показанные коды восстановления вне компьютера, с которого входите. Каждый код срабатывает один раз; новые можно выпустить на той же странице.

После этого при входе после пароля спрашивается код. Если телефона нет: «Использовать код восстановления».

Правила проверки кодов:
- код принимается в пределах текущего 30-секундного шага и одного соседнего (`codeWindow(1)`);
- принятый код повторно не принимается, как и более ранние коды;
- код восстановления срабатывает один раз;
- после 5 неверных кодов (TOTP и восстановления вместе) за 15 минут коды этого администратора не принимаются до конца окна (`App\Auth\MfaThrottle`, считается по администратору, а не по адресу);
- для подключения и отключения нужен текущий пароль аккаунта и код.

Пароль аккаунта хранится в схеме `accounts` в формате ASP.NET Identity; подтверждение пароля в панели проверяет его через `App\Auth\ZaparaHasher`. Собственные хэши панели (коды восстановления) остаются bcrypt.

### Выкатка без блокировки

1. Деплой с выключенным требованием (по умолчанию `ZAPARA_ADMIN_MFA_REQUIRED=false`). Миграции панели
   контейнер `admin` выполняет сам при старте (`php artisan migrate --force`, повторный запуск ничего не меняет;
   отключается `ZAPARA_ADMIN_MIGRATE_ON_START=false`). Перед миграцией `php artisan admin:migrate-preflight` проверяет схему,
   права и конфликтующие таблицы (см. «База данных и права» ниже). Если проверка или миграция не прошла, контейнер не стартует,
   причина в `docker compose logs admin` (строки `admin: ...`).
   Без требования все входят как раньше, подключившие TOTP вводят код.
2. Каждый администратор подключает TOTP по шагам выше.
3. В `admin.env` ставят `ZAPARA_ADMIN_MFA_REQUIRED=true` и перезапускают `admin`. С этого момента администратора без TOTP после пароля сразу отправляют на подключение, в остальные разделы панели без него не пустит.

Пока требование выключено, не подключивший TOTP администратор защищён только паролем. Включайте требование сразу после того, как все подключили.

### Если администратор потерял и телефон, и коды

Оператор с доступом к базе удаляет его строку, после чего администратор подключает TOTP заново при следующем входе:

```sql
DELETE FROM admin_mfa_credentials WHERE user_id = '<user_id из accounts.users>';
```

## База данных и права

Панель подключается к той же базе PostgreSQL, что и Zapara.Server (`DB_HOST`, `DB_DATABASE`, `DB_USERNAME`, ... в `admin.env`).
Таблицы сервера панель адресует по имени схемы (`accounts`, `admin`, `communities`, `operator`; имена задаются
`ZAPARA_*_SCHEMA`). Собственные таблицы панели (`migrations`, `users`, `password_reset_tokens`, `sessions`, `cache`,
`cache_locks`, `jobs`, `job_batches`, `failed_jobs`, `admin_mfa_credentials`) создаются её миграциями в схеме
`DB_SCHEMA` (по умолчанию `public`, как раньше).

Если в этой схеме уже есть чужая таблица с тем же именем (например, `users`), её не трогают: укажите панели отдельную
схему. Схема создаётся заранее, а затем перезапускается контейнер:

```sql
CREATE SCHEMA panel AUTHORIZATION <роль панели>;
```

```env
DB_SCHEMA=panel
```

При переносе уже работающей панели в новую схему её таблицы создаются заново: сессии сбрасываются, а TOTP
администраторы подключают заново, если не перенести `admin_mfa_credentials` вручную.

Права роли панели (`<роль>` — `DB_USERNAME`; если это владелец базы, как `zapara` в `deploy/server/compose.yml`, всё уже есть):

```sql
-- собственная схема панели: миграции при старте контейнера
GRANT USAGE, CREATE ON SCHEMA public TO <роль>;          -- или схема из DB_SCHEMA
-- схемы сервера: чтение и изменение тех таблиц, с которыми работает панель
GRANT USAGE ON SCHEMA accounts, admin, communities, operator TO <роль>;
GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA accounts, admin, communities, operator TO <роль>;
```

Начиная с PostgreSQL 15 право `CREATE` на схему `public` по умолчанию есть только у владельца базы, поэтому
отдельной роли его нужно выдать явно. Если создавать таблицы роли панели нельзя, миграции применяют отдельно
(`php artisan migrate --force` с привилегированной ролью), а в `admin.env` ставят `ZAPARA_ADMIN_MIGRATE_ON_START=false`.

`admin:migrate-preflight` останавливает старт сразу, без повторов (контейнер завершается с кодом 1), если:
- схемы `DB_SCHEMA` нет;
- есть неприменённые миграции, а у роли нет `USAGE` и `CREATE` на эту схему;
- таблица, которую создала бы неприменённая миграция, уже есть и создана не ею (для `admin_mfa_credentials` проверяется набор колонок);
- таблица `migrations` в схеме не похожа на таблицу миграций Laravel.

Каждая проблема выводится одной строкой `admin: ...` с нужной командой. Недоступная база (ещё стартует) — не ошибка
настройки: проверка повторяется до 5 раз с паузой 3 с.
